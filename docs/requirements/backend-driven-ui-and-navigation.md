# 后端驱动界面与导航复用需求

本文档记录当前项目在“后端重、前端轻”方向上的后续改造范围。后端负责业务结构、权限和文案，前端负责通用协议渲染与少量已打包的专用组件。

## 1. 当前已完成

- [x] 阿里云菜单和 API 从 `base` 拆分为独立代码站点 `server/sites/aliyun/`。
- [x] Node 启动时根据构建期代码站点注册表幂等同步 `global_sites`。
- [x] Worker 构建与 Node 数据库初始化分离；构建不再自动打开 SQLite 或执行 Node 初始化。
- [x] 站点、域名和用户状态使用 Switch 编辑，并继续以 `enabled/disabled` 字符串存储。
- [x] 状态值和启用/禁用显示选项提取到 `shared/types/status.mts`。
- [x] 导航树的路径解析、继承合并、角色过滤和页面收集提取到 `shared/navigation-tree.mts`。
- [x] 前端和后端共用页面定义收集逻辑，避免导航规则分叉。

## 2. 后端驱动按钮

### 2.1 目标

列表、表单和页面操作按钮由后端输出，后端决定：

- 是否显示；
- 显示文案；
- 按钮顺序；
- 是否禁用；
- 是否需要确认；
- 动作类型；
- 动作参数。

前端不再硬编码具体业务按钮名称、业务按钮权限或业务按钮顺序。

### 2.2 标准 CRUD 动作

标准 CRUD 动作不由后端重复提供路径。前端根据当前页面的 `resourcePath`、行主键和动作类型生成 API 路径：

```text
create -> POST   /api/<resourcePath><apiSuffix>
edit   -> PUT    /api/<resourcePath>/<id><apiSuffix>
delete -> DELETE /api/<resourcePath>/<id><apiSuffix>
refresh -> 重新加载当前资源
```

后端只需提供类似以下语义配置：

```ts
{
  key: 'delete',
  label: '删除',
  action: 'delete',
  confirm: '确认删除吗？'
}
```

API 路径相对于 `/api`，业务配置不重复写 `/api`，也不重复写 `.php` 等后缀。路径前缀和后缀仍由前端通用协议助手处理，这属于基础设施逻辑，不属于业务硬编码。

### 2.3 非标准动作

同步云资源、执行迁移、导出数据等无法从 CRUD 规则推导的操作，使用受限的动作标识：

```ts
{
  key: 'migrate',
  label: '执行迁移',
  action: 'migrate'
}
```

前端只执行预先注册的通用动作，不执行后端下发的 JavaScript。后端 API 仍必须独立完成权限校验，按钮隐藏不能替代接口鉴权。

## 3. 文案与多语言

- [ ] 后端根据请求语言或用户语言配置返回菜单、按钮、字段、确认提示和反馈文案。
- [ ] 前端不维护业务语言包。
- [ ] 数据库和 API 中的稳定值不翻译，例如 `enabled`、`disabled`、`delete`。
- [ ] 显示文本与稳定程序值分离，避免把中文文案作为业务判断条件。
- [ ] 通用 UI 必要的框架文案可以保留在前端，业务文案必须由后端提供。

## 4. 导航与路径

- [x] 站点导航继续由 `server/sites/<site_key>/navigation.mts` 声明。
- [x] 站点继承、角色过滤和导航覆盖继续由后端负责。
- [x] 前后端共用纯导航树算法，不把业务导航搬回前端。
- [ ] 统一页面路径和 API 路径助手，减少前端各处字符串拼接。
- [ ] 明确约定：导航 `key` 是逻辑页面路径，前端统一追加页面后缀；API 资源路径相对于 `/api`，前端统一追加 API 后缀。
- [ ] 为页面路径和 API 路径助手增加测试，覆盖无后缀、`.html`、`.php`、动态 ID 和首尾斜杠。

## 5. 前端职责边界

前端保留以下能力：

- 通用菜单和页面渲染；
- 通用表格、表单、Switch、Select 等控件；
- 受限动作执行器；
- 少量已打包的复杂业务组件注册表，例如阿里云实例详情组件；
- 浏览器路由和页面后缀拼接。

前端不负责：

- 决定业务菜单是否显示；
- 决定业务按钮权限；
- 维护业务页面标题和业务按钮文案；
- 维护具体业务 API URL；
- 通过隐藏按钮实现安全控制。

## 6. 实施顺序

1. 抽取页面路径和 API 路径助手。
2. 为 `TableCRUD` 增加后端驱动的标准动作配置。
3. 将编辑、删除、刷新等现有按钮迁移到动作配置。
4. 增加非标准动作注册表和动作执行器。
5. 将站点、域名、用户等管理页面的按钮权限迁移到后端输出。
6. 增加语言参数和后端文案解析层。
7. 为按钮、路径和多语言协议增加 Node/Worker Smoke 测试。

## 7. 明确不做

- 不把业务导航和权限规则整体搬到前端。
- 不让后端下发可执行代码。
- 不为标准 CRUD 按钮重复返回完整 `href`、`url` 和 `path`。
- 不使用按钮隐藏替代后端 API 权限校验。
- 不为了抽象而建立覆盖所有业务差异的通用 CRUD 框架。
